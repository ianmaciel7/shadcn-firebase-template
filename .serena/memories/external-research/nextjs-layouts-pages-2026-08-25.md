## Durable findings

- App Router uses file-system routing: a segment becomes a public page when its `page` file default-exports a React component. Nested directories define nested URL segments.
- A root `layout` is required. It default-exports a component accepting `children` and includes the document `html` and `body` elements. Descendant layouts automatically nest and wrap their child segments.
- Dynamic route segments use bracketed directory names, such as `[slug]`. In the documented asynchronous contract, pages and layouts await their `params` promise before reading values.
- Server Component pages receive `searchParams` as a promise. Reading it requires request-time data and therefore opts the page into dynamic rendering. Use it for data loading; use `useSearchParams` only for client-side state derived from already-loaded data. Event handlers can read `window.location.search` with `URLSearchParams` when no reactive value is needed.
- Use `next/link` as the primary navigation API: it extends anchors with prefetching and client-side navigation. Reserve `useRouter` for advanced navigation flows.
- Globally generated `PageProps<'/route'>` and `LayoutProps<'/route'>` infer route params, `searchParams`, children, and named parallel-route slots. They are generated by `next dev`, `next build`, or `next typegen`; static routes resolve `params` to `{}`.
